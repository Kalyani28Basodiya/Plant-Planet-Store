📅 Day 1–2 — Next.js App Router
⚡

Next.js 15+ App Router

Day 1 – 2
App Router vs Pages Router
Pages Router purana tha (pages/), App Router naya hai (app/) — ye project App Router use karta hai
Server Components vs Client Components
By default sab Server Components hain — "use client" likhne se Client Component banta hai. Navbar, Cart — client; API fetch — server.
Dynamic Routes — [slug]
app/products/[slug]/page.tsx — URL se dynamic value milti hai
Route Handlers (API Routes)
app/api/products/route.ts — GET, POST functions export karte hain
Layout.tsx — Shared Layout
app/layout.tsx — Navbar aur Footer yahan wrap hote hain, har page pe show hote hain
Special Files
page.tsx, layout.tsx, loading.tsx, error.tsx, not-found.tsx — Next.js inhe automatically use karta hai

💡 Interview Answer

Q: App Router mein Server aur Client component ka difference?
Server Components server pe render hote hain — direct DB access possible, JavaScript bundle mein nahi jaate. Client Components browser pe hydrate hote hain — state, events ke liye zaroori hain. "use client" directive use karo.

📅 Day 3–4 — MongoDB + Mongoose
🍃

MongoDB + Mongoose

Day 3 – 4
MongoDB kya hai?
NoSQL database — JSON-like documents store karta hai, tables nahi. Plant Planet mein Products, Users, Orders store hote hain
MongoDB Atlas
Cloud-hosted MongoDB — .env mein MONGODB_URI se connect hota hai
Mongoose ODM
Object Document Mapper — JavaScript objects ko MongoDB documents mein map karta hai
Schema & Model
Schema = structure define karo (field names, types, validation). Model = Schema se collection banao
CRUD Operations
Model.find(), Model.findOne(), Model.create(), Model.findByIdAndUpdate(), Model.deleteOne()
Connection Pooling — lib/mongodb.ts
Ek hi connection bar-bar nahi kholte — cached connection use karte hain (global variable trick)

💡 Interview Answer

Q: SQL vs MongoDB kab choose karein?
MongoDB tab jab data structure flexible ho (products ke alag-alag fields), rapid development ho, ya JSON-like nested data ho. SQL tab jab strict relations hain aur ACID transactions zaroori hain (banking apps).

📅 Day 5–6 — NextAuth.js (Authentication)
🔐

NextAuth.js v4

Day 5 – 6
NextAuth kya karta hai?
Authentication system ready-made — Login, Session, Logout sab handle karta hai
Credentials Provider
Email + Password se login — app/api/register/route.ts mein user create, authorize() function mein verify
JWT Tokens
Login ke baad JWT token banta hai — browser mein cookie/localStorage mein store hota hai, har request ke saath bheja jaata hai
Session — useSession()
Client side pe current user ka data milta hai — session.user.email, session.user.name
SessionWrapper — components/SessionWrapper.tsx
SessionProvider se wrap karte hain taaki poori app mein session accessible ho
Bcryptjs — Password Hashing
Password plain text mein kabhi save nahi karte — bcrypt.hash(password, 10) se hash banate hain, bcrypt.compare() se verify karte hain

💡 Interview Answer

Q: Why hash passwords?
Agar database hack ho jaye toh plain text passwords directly expose ho jaate hain. Bcrypt hashing one-way hai — hash se original password nahi nikal sakte. Salt automatically add hota hai jo rainbow table attacks rokta hai.

📅 Day 7 — Zustand (State Management)
🐻

Zustand

Day 7
Zustand kya hai?
Lightweight global state management — Redux se zyada simple, no boilerplate
Store Create karna
store/cartStore.ts — create() function se store banate hain, state + actions ek jagah
Store Use karna
const { cart, addToCart, removeFromCart } = useCartStore() — kisi bhi component mein directly use
Persist Middleware
Cart data localStorage mein save rehta hai — page refresh ke baad bhi cart nahi jaata

💡 Interview Answer

Q: Zustand vs Redux?
Zustand mein no Provider wrapping, no actions/reducers/dispatch ceremony. Bas ek create() call — state aur functions ek jagah. Chhote-medium projects ke liye perfect. Redux tab jab DevTools, time-travel debugging, ya very complex state logic chahiye.

📅 Day 8 — TanStack React Query
📡

TanStack Query (React Query v5)

Day 8
React Query kya hai?
Server state management — API calls ko cache karna, background refetch, loading/error states automatically handle
useQuery
Data fetch karne ke liye — queryKey (cache ID) + queryFn (fetch function) deta hai
useMutation
Data create/update/delete ke liye — POST/PUT/DELETE calls
QueryProvider Setup
components/QueryProvider.tsx — QueryClientProvider se app wrap karte hain
Caching + Stale Time
Same query bar-bar call nahi hoti — cache se milti hai. staleTime set kar sakte hain

💡 Interview Answer

Q: useEffect se fetch vs React Query?
useEffect se: no caching, manually loading/error state manage karna, race conditions possible. React Query mein: automatic caching, deduplication, background sync, retry logic, pagination support — sab built-in.

📅 Day 9 — Razorpay Payment Integration
💳

Razorpay

Day 9
Payment Flow — 3 Steps
1️⃣ Backend pe order create karo → 2️⃣ Frontend pe Razorpay popup open karo → 3️⃣ Backend pe payment verify karo
Order Create — app/api/create-order/route.ts
Razorpay SDK se order ID generate karte hain — amount, currency pass karte hain
Checkout Page
Razorpay script load karo, order ID pass karo, popup open hota hai — user pay karta hai
Payment Verification
HMAC signature verify karte hain — razorpay_order_id + razorpay_payment_id se signature match karni padti hai
Environment Variables
RAZORPAY_KEY_ID aur RAZORPAY_KEY_SECRET — .env mein store, kabhi frontend pe expose mat karo

💡 Interview Answer

Q: Payment ke baad order kaise save karte ho?
Payment successful hone ke baad callback mein /api/orders pe POST call karte hain — user ID, cart items, payment ID, total amount MongoDB mein save hota hai. Tab hi order confirm hota hai.
